## 前回のあらすじ

厚労省の緊急避妊薬薬局データ。営業時間フィールドが完全自由記述で6,933種。正規表現82個を積み上げてカバー率97.1%まで到達、「いい加減ここが潮時だ」と記事を書いて[薬局検索サイト](https://odakin.github.io/mhlw-ec-pharmacy-finder/)をリリースした。

で、リリースしたら動作確認するわけだ。

土曜の午後に検索結果を眺めている。50件の薬局が出てくる。大半は閉まっているはずなのに全部表示される。実際にこのサイトを使う人は緊急避妊薬を探している人だ。時間がない。閉まっている薬局を1件ずつスクロールして営業時間を目視確認する余裕はない。

営業時間はもう構造化データになっている。`if (now >= open && now < close)` で済む。ある晩に座って書き始めて、日付が変わる頃には動いていた。

動いていた。ただし答えが間違っていた。

---

## パースできてる ≠ 答えが正しい

パーサーの出力はこう:

```
入力: 月-金:9:00-18:00,土:9:00-13:00,日祝休み

出力: { schedule: [
         {days:["月","火","水","木","金"], open:"9:00", close:"18:00"},
         {days:["土"], open:"9:00", close:"13:00"}
       ],
       holidayClosed: true }
```

これは正しい。パーサーの仕事は完璧だ。

さて、1月12日（月曜）の朝10時。この薬局は開いているか？

月-金 9:00-18:00。月曜は含まれている。10時は範囲内。フィルターは「営業中」。

ところが1月12日は成人の日だ。データには `日祝休み` と書いてある。パーサーは `holidayClosed: true` をちゃんと抽出している。でもフィルターの判定ロジックは曜日スケジュールだけ見ていて、祝日フラグを見ていなかった。

パースは正しい。解釈が間違っている。ユーザーは「営業中」を信じて行く。閉まっている。

緊急避妊薬を探している人にこれをやったら洒落にならない。

## 祝日計算エンジンを書く羽目になった

祝日判定なしに「今開いている」は成り立たない。ということで営業時間パーサーのコードベースに祝日計算エンジンが生えた。約60行、外部依存ゼロ。

日本の祝日は固定日（元旦、建国記念日など）だけでなく:

- **ハッピーマンデー**: 「1月の第2月曜日」式。成人の日、海の日、敬老の日、スポーツの日
- **春分・秋分**: 天文公式で計算。年によって日が変わる
- **振替休日**: 祝日が日曜と重なったら翌月曜が休み
- **国民の休日**: 祝日に挟まれた平日が休みになる

春分は天文計算:

```javascript
const vernal = Math.floor(
  20.8431 + 0.242194 * (year - 1980)
  - Math.floor((year - 1980) / 4)
);
```

~2099年まで有効。正規表現パーサーに軌道力学が必要になるとは思わなかった。

ちなみに祝日計算自体はフィルターより前（パーサー開発中）に `holidayClosed` フラグの判定用として書いていた。問題だったのは、「今開いている」の判定がそのフラグを参照していなかったこと。仕組みはあるのに繋がっていないというパターン。

## キャッシュが嘘をつく

同じ晩に見つけたもう1つのバグ。

サイトは10,000件のパース結果をキャッシュしている。毎回パースし直すと遅いから。キャッシュキーは生テキスト。テキストが同じならキャッシュヒット。

`月-金:9:00-18:00,日祝休み` は、普通の月曜には「営業中」、祝日の月曜には「休み」を返すべき。でもテキストは変わらない。キャッシュは普通の月曜に計算した「営業中」を祝日にも返す。

たまたま祝日近くにテストしていたから気づいた。普通の平日だけでテストしていたら、祝日のたびに静かに嘘をつき続けるバグが出荷されていた。

修正: 祝日判定はキャッシュの外で毎回やり直す。

---

## 1週間後に見つかった穴: 定休日

フィルターはその晩に完成して、毎日使っていた。1週間くらい経った水曜日、確か定休日のはずの薬局が「営業中」と表示されているのに気づいた。

生データを見る:

```
月-金:9:00-18:00（水曜定休）
```

パーサーは `月-金:9:00-18:00` を正しくパースしている。月火水木金、全部 9:00-18:00。水曜の10時にフィルターを使うと「営業中」。

でも `（水曜定休）` と書いてある。この情報、パーサーが拾っていなかった。

### 定休日という新しい地獄

定休日の書き方は案の定バリエーション豊か:

```
定休日：水・日              ← 明示的リスト
月-土（水曜を除く）          ← 「除く」パターン
水曜休み                    ← 「X休み」
（木・土午後休診）            ← 午後だけ休み（医療機関に多い）
月-金（祝日除く）            ← 祝日除外
```

正規化パイプラインの**前に**定休日を抽出するフェーズを追加した。正規化が始まるとテキストが書き換わって元の情報が失われるから、先に取り出す必要がある。

抽出した定休日は `applyClosedDays()` でスケジュールから除去する。ただし曖昧なケースでは適用しない。水曜だけ別の営業時間を持つエントリがある場合、「水曜定休」と矛盾するが、どちらが正しいか判断できない。判断できないなら触らない。

この開発全体を通して収束した設計原則:

> **正しい > 注記つきで正しい > 不明 > 間違い**

迷ったら「わからない」を選ぶ。「間違い」は選ばない。営業していない薬局を「営業中」と表示するくらいなら、「営業状況は店舗にご確認ください」のほうがずっとマシだ。

## 結果

| 指標 | 前回記事 | 現在 |
|------|---------|------|
| 薬局カバー率 | 97.1%（9,659/9,951件） | 98.2%（9,768/11,734件） |
| 医療機関 | — | 88.3%（2,739/3,107件） |
| 祝日計算 | 基本 | 年間18日、天文公式 |
| 定休日抽出 | なし | 5パターン |

分母が増えている（厚労省がデータを追加した）のに率も上がった。医療機関データも追加。医療機関は「午前診/午後診」「休診日」など薬局と違う語彙で、また別の味の地獄。

## 教訓

**ユーザーの目で見ろ、すぐに。** 「今開いている」は誰かに言われたんじゃなく、自分で動作確認していて「これだと使う人が困る」と気づいた。祝日バグもキャッシュバグも、開発者目線だけでテストしていたら何ヶ月も気づかなかったはず。

**パースと解釈は別の問題。** テキスト→構造化データがパース。構造化データ→「今開いている？」が解釈。パーサーが100%正しくても、解釈層にバグがあれば答えは間違う。前回「正規表現82個でパースした」と書いたが、パースはこの仕事の半分でしかなかった。

**時間に依存する機能はカレンダーの多様性でテストしろ。** 普通の火曜に動いても祝日の月曜に動くとは限らない。テストケースに祝日・年末年始・閏年を入れないと、1年の95%で正しく5%で嘘をつくコードができる。

**キャッシュは日付を知らない。** テキストが同じでも、今日が平日か祝日かで答えが変わる。キャッシュキーにコンテキストを含めないと、昨日の真実を今日も返す。
