## これまでのあらすじ

厚労省の緊急避妊薬薬局データ。営業時間が完全自由記述で、一意なフォーマットが6,933種。正規表現82個でカバー率97.1%まで持っていって、「まあここが潮時かな」と記事を書いてリリースした。

[薬局検索サイト](https://odakin.github.io/mhlw-ec-pharmacy-finder/)として公開して、使ってもらえるようになって、ひと段落ついたと思ったところにリクエストが来た。

**「今開いてる薬局だけ絞り込めませんか？」**

営業時間はもうパース済みだ。現在時刻と比較して範囲内ならtrue。半日で終わる。

2週間かかった。しかも見つかったバグの大半は「パーサーは正しいのに答えが間違っている」という新ジャンルだった。

---

## パースと解釈は別の問題だった

パーサーの仕事はテキストを構造化データに変換すること:

```
月-金:9:00-18:00,土:9:00-13:00,日祝休み
→ { schedule: [{days:["月","火","水","木","金"], open:"9:00", close:"18:00"},
               {days:["土"], open:"9:00", close:"13:00"}],
    holidayClosed: true }
```

ここまでは前回やった。「今開いている」フィルターがやるのは、この構造化データを**今この瞬間**に対して評価すること。パースと解釈。別の問題だとは、やるまで気づかなかった。

---

## バグ1: 祝日が見えない

月曜の朝9時半。スケジュールは月-金 9:00-18:00。フィルターは「営業中」と返す。

ただし今日は成人の日だ。データには `日祝休み` と書いてある。パーサーは `holidayClosed: true` を抽出済み。でも「今開いている」の判定ロジックは曜日スケジュールだけ見ていて、祝日フラグを無視していた。

祝日判定を一から実装することになった。約60行、外部ライブラリなし:

- 固定祝日（元旦、建国記念日、天皇誕生日…）
- ハッピーマンデー（成人の日、海の日、敬老の日、スポーツの日）
- 春分・秋分（天文公式で計算。2099年まで有効）
- 振替休日（日曜に重なったら翌月曜）
- 国民の休日（祝日に挟まれた平日）

春分の日は天文計算:

```javascript
const vernal = Math.floor(
  20.8431 + 0.242194 * (year - 1980)
  - Math.floor((year - 1980) / 4)
);
```

「営業時間パーサーのついでに祝日計算エンジンを書く」は人生で一度あるかないかの体験だった。

## バグ2: 定休日がテキストに埋もれている

```
月-金:9:00-18:00（水曜定休）
```

パーサーは `月-金:9:00-18:00` を正しくパースする。月火水木金、全部 9:00-18:00。

水曜に「今開いている」フィルターを使う。月-金のスケジュールに水曜が含まれているから「営業中」。

でも実際は水曜定休だ。`（水曜定休）` はテキストの中に書いてあるのに、パーサーが拾っていなかった。

### 定休日という新しい地獄

定休日の書き方が案の定カオス:

```
定休日：水・日              ← 明示的な定休日リスト
月-土（水曜を除く）          ← 「除く」パターン
月-金（祝日除く）            ← 祝日を除外
水曜休み                    ← 「X休み」パターン
（木・土午後休診）            ← 午後だけ休み（医療機関）
```

パーサーの正規化パイプラインの**前**に、定休日を抽出するフェーズを挟んだ。正規化が始まると元テキストの情報が失われるから、先に取り出しておく必要がある。

抽出した定休日は `applyClosedDays()` でスケジュールから除去する。ただし**曖昧なケースでは適用しない**。たとえば水曜だけ別の営業時間を持つエントリがある場合、「水曜定休」と矛盾する。どちらが正しいか判断できないなら、触らない。

ここで確立した設計原則:

> **正しい > 注記つきで正しい > 不明 > 間違い**

「わからない」は「間違い」より常にマシ。緊急避妊薬を探している人に「この薬局は今開いています」と表示して、行ったら閉まっていたら取り返しがつかない。

## バグ3: キャッシュが祝日を知らない

地味だけど一番怖かったバグ。

サイトは10,000件以上のデータをパースするので、結果をキャッシュしている。キャッシュキーは生テキスト。テキストが変わらなければキャッシュを使う。

問題: 同じ `月-金:9:00-18:00,日祝休み` というテキストが、普通の月曜には「営業中」、祝日の月曜には「休み」を返すべきなのに、キャッシュは「普通の月曜の結果」を返し続ける。テキストは変わっていないから。

修正: 日付をキャッシュのコンテキストに含める。祝日判定はキャッシュヒット時でも毎回やり直す。

「キャッシュが正しいデータを返しているのに答えが間違っている」。これは `console.log` で追っても見つけにくい。たまたま祝日にデバッグしていて気づいた。

## カバー率は上がり続ける

「今開いている」フィルターの開発中、パーサー本体のエッジケースも次々見つかった。直すたびに全体のカバー率が上がる:

| 時点 | 薬局カバー率 | 備考 |
|------|------------|------|
| 前回記事 | 97.1%（9,659/9,951件） | 正規表現82個 |
| 現在 | 98.2%（9,768/11,734件） | データも増えた |

分母が増えている（厚労省がデータを追加した）のに率も上がった。さらに医療機関データ（3,107件）も対応して、88.3%。医療機関はフォーマットの傾向が薬局と違う（「午前診/午後診」みたいな医療用語が多い）ので、また別の地獄がある。

パース不能として残っているのは `外来診療時間内`（そもそも時刻情報がない）や Excel コピペのタブ区切りなど、構造的に対応不能なもの。これは前回と同じく、パース不能なら生テキストを表示する。

---

## 今回の教訓

**パースと解釈を混同しない。** テキスト→構造化データは「パース」。構造化データ→「今開いている？」は「解釈」。パーサーが正しくても解釈層にバグがあれば答えは間違う。前回の記事で「正規表現82個でパースできた」と言い切ったが、パースは半分でしかなかった。

**時間に依存する機能は「今日」だけテストしても足りない。** 普通の火曜日に動いても、祝日の月曜に動くとは限らない。テストケースにカレンダーの多様性が必要。

**キャッシュは解釈層の一部。** キャッシュが日付を知らなければ、昨日の真実を今日も返す。

**曖昧なら触るな。** 定休日の適用で「たぶんこうだろう」と推測するより「わかりません」と言うほうが、このドメインでは100倍安全。前回の記事の教訓「間違いより欠落のほうがマシ」は、「今開いている」フィルターで一段と切実になった。
